## Что такое Truffles

**Одной фразой:**
> Виртуальный консультант, который отвечает по фактам в любое время и ведёт к следующему шагу.

**Формула:**
```
Truffles = Deterministic Core (безопасность/состояния/факт‑коммит через tools/packs)
        + LLM (понимание и формулировка, но НЕ факты)
        + Escalation (выход к человеку)
        + Data in KZ (суверенность и изоляция)
```

---

## Ценность (для кого)

| Для кого | Что получает |
|---|---|
| Клиент бизнеса | Быстрый ответ в любое время + понятный следующий шаг |
| Владелец бизнеса | Меньше потерь заявок, меньше рутины, стабильный стандарт ответов |
| Менеджер | Получает только сложное и важное, с контекстом и статусом |

---

## Позиционирование

- **МСБ:** продаём результат (“консультант + запись + порядок в заявках”), а не слово “AI”.
- **Enterprise:** продаём контроль (compliance, аудит решений, локализация данных, изоляция клиентов).
- **Инвесторы/тех аудитория:** платформа с детерминированным ядром и контролируемым LLM.

---

## Почему мы существуем (ключевые боли)

1) **«Не успеваю отвечать — теряю клиентов»** (ночь/выходные/пиковые часы).  
2) **«Одни и те же вопросы каждый день»** (FAQ‑80%).  
3) **«Заявки теряются без статуса и эскалации»** (нет прозрачности).  
4) **«Данные нельзя отдавать куда попало»** (локализация/безопасность).

# Принципы (нарушать нельзя)

## Принцип 1: Качество ядра важнее количества фич
Если бот отвечает плохо — всё остальное бессмысленно.

## Принцип 2: Truth‑first, а не “умный чат”
- **Факты только из data packs** (client_pack/domain_pack).  
- Нет факта → **уточнение (до 2 раз)** → **эскалация**.

## Принцип 3: Deterministic Core для безопасности и фактов
Hard‑LAW/policy/state и факт‑коммит выполняются **детерминированно** через tools/packs, без LLM‑фактов.

## Принцип 4: LLM — для понимания и подачи, не для фактов
LLM даёт intent/slots и формулировку, но решение подтверждается валидаторами; Response Guard блокирует лишнее.

## Принцип 5: Эскалация — уважение, а не провал
Клиент всегда может выйти к человеку быстро. Эскалация — это отдельный продукт и источник обучения.

## Принцип 6: Суверенность данных и изоляция
Данные клиентов хранятся в КЗ, а tenant/branch изолированы так, чтобы не было утечек между заказчиками.

## Принцип 7: Один Decision Graph
Решения идут по фиксированной цепочке стадий. Никакой “магии”, которая расползается по коду.

## Принцип 8: Trace/meta обязательны
Без trace/meta решение считается несуществующим: нельзя отлаживать, доказывать качество или масштабироваться.

## Принцип 9: EVAL‑gate в CI
CORE‑eval блокирует релиз. Без этого проект превращается в ручной хрупкий набор исключений.

## Контракт продукта (3 исхода)

В каждом сообщении бот должен привести диалог к одному из исходов:
- **FACT** — короткий факт‑ответ (info/consult) строго из data packs.
- **COLLECT** — сбор слотов записи/лида (expected_reply_type).
- **HANDOFF** — передача человеку (pending/manager_active) с прозрачным статусом.

Если факта нет → **уточнение (макс 2)** → иначе **эскалация**.

---

## Что НЕЛЬЗЯ обещать/делать

- Подтверждение/проверка оплат, возвраты, банковские операции → **только эскалация**.
- Медицинские советы/противопоказания/аллергии/ожоги/кровь → **только эскалация**.
- Скидки/способы оплаты — **только если явно разрешено** правилами в policy/data pack.
- “Свободные слоты” без подключённого провайдера доступности (calendar/CRM) — **не обещать**, только сбор предпочтений.

---

## Отличия от типовых чатботов

- Не “обёртка над ChatGPT”: решения и факты контролируются.
- “Суверенный AI”: локализация данных + контроль.
- Открытая логика: аудит, прозрачный пайплайн, trace.
- Эскалация как UX‑ядро: статусы, прозрачное ожидание, Telegram‑UI, обучение.

---

## Метрики успеха (North Star)

- **Quality Deflection** (не просто deflection).
- **Goal Completion** (диалог доведён до FACT/COLLECT/HANDOFF).
- **CSAT**.

---

## Доказуемость (как понимаем, что работаем правильно)

- На каждое user‑сообщение пишется **decision_trace + decision_meta**.
- Любая фича считается “сделано” только если есть **evidence** в `STATE.md`.
- Релиз возможен только при зелёном **CI CORE** (без зависимости от внешнего LLM‑ключа).

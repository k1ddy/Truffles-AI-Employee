# DEC-2026-03-30 — Consultant Core Architecture Recovery Governing Decision

- Status: accepted
- Owner: Top Architect / Brain
- Date: 2026-03-30

## Decision

The governing consultant-core architecture is now fixed as:

`Single Semantic Owner + Strict Binding Boundary + Canonical Continuity State + First-Class Fact Plane + Adapter-only Legacy Mesh + Black-box Quality Plane`

This is not a slogan. It is the repository law for all future consultant-core work.

The project explicitly rejects the earlier simplification that made the first active recovery move a fact-family slice. `location / hours / parking` is a useful later proving slice, but it is not the root cause. The root cause is system-level authority topology:
- semantic ownership is not fully closed;
- truth carriers still compete;
- deterministic boundary still overreaches;
- pack/runtime separation is still false in live paths;
- legacy compatibility mesh still co-owns behavior;
- governance was more truthful than preventive.

Therefore the required recovery order is root-first:
1. authority topology and writer-law enforcement
2. truth-carrier inventory and freeze
3. adapter-only legacy mesh and caller proof
4. planner/executor post-owner reconstruction constriction
5. boundary/degrade constriction
6. fact-plane materialization
7. first fact-family cutover
8. touched-slice continuity normalization
9. legacy drain and full proof closure

## Why

The external packet and live code show that the repeated patch-loop is not primarily caused by wording defects or one family of fact replies. The repeated patch-loop is caused by multiple layers still holding decision power after the intended semantic owner has already spoken.

Visible symptom families, including `parking -> address + hours`, matter only because they surface this deeper structure.

## Root-Cause Stack

### 1. Distributed authority
The hot path is real, but it is not the only governor. Meaning, continuity, fact scope, and fallback behavior still travel through multiple layers.

### 2. No single enforced writer law
The semantic owner exists directionally, but downstream layers still reconstruct semantic-adjacent artifacts.

### 3. Multiple truth carriers
Canonical continuity state exists, but compatibility and transport carriers still compete with it.

### 4. Boundary overreach
Deterministic layers still do more than validate / deny / degrade / preserve.

### 5. Missing fact plane
Fact selection, composition, rendering, and fallback are still mixed.

### 6. False pack/runtime separation
Pack adapters still embed behavior authority instead of remaining declarative or renderer-bounded.

### 7. Live legacy mesh
Compatibility surfaces are still real co-owners, not dead wrappers.

### 8. Governance mismatch
Forensics became accurate before runtime governance became self-constraining.

## Governing Architecture Contract

### Semantic Plane
Exactly one hot-path component may author turn meaning.
It owns:
- requested outcome / action
- interaction intent
- pending-question intent
- slot / referent state needed for the turn
- requested fact scope
- semantic provenance required by contract

### Binding Plane
Deterministic binding may:
- validate schema and admissibility
- authorize or deny execution
- narrow an owner request
- attach reason codes and observability

Deterministic binding may not:
- invent meaning
- widen fact scope
- mint a new pending-question intent

### Continuity Plane
One canonical continuity substrate exists for mutable runtime state.
Compatibility carriers may exist temporarily only as derived adapters with explicit deletion ownership and expiry.

### Fact Plane
The runtime must carry explicit fact objects:
- owner-authored fact request
- binding-authored fact plan
- resolver/renderer-authored fact result

Fact scope may widen only when an explicit allowed emitted set authorizes it.

### Legacy Plane
Legacy modules may transport, format, shadow-compare, or bridge. They may not own meaning, continuity truth, or fact composition.

### Quality Plane
Replay, evaluator, and audit are black-box observers. They may not reinterpret runtime semantics into new truth.

## No Partial Closure Law

A block is unacceptable if any of the following remain true inside the declared mechanism envelope:
- a live writer or live caller still bypasses the intended contract;
- a legacy path still co-owns the same mechanism;
- sibling paths of the same mechanism are left unresolved but omitted from scope;
- the block moves code but not authority;
- acceptance relies on wording rather than executable contract;
- replay or human semantic audit is missing.

No task is accepted merely because checklist points were executed. A task is accepted only when the system behavior and the architecture of the declared slice actually satisfy the required result.

## Migration Law

The next admissible move is not another runtime symptom fix.
The next admissible move is to materialize the live authority topology and enforce writer laws repository-wide before any runtime slice resumes.

## Rejected Paths

The repository now explicitly rejects:
- local hotspot patching as the default strategy;
- treating one visible family as the root cause;
- regex/phrase semantic routing in core;
- rewrite-first plans without bounded extraction order;
- deleting legacy surfaces before caller proof;
- claiming recovery from evaluator output or packet quality alone.

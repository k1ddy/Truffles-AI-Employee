## One web search (mandatory before implementation)

- Query: `OpenAI structured outputs json_schema top level allOf anyOf not allowed official docs`
- Time (UTC): `2026-03-06T03:39:00Z`
- Sources:
  - `https://platform.openai.com/docs/guides/structured-outputs`
  - `https://openai.com/index/introducing-structured-outputs-in-the-api/`
- Ready solutions found:
  - OpenAI Structured Outputs требует корневой `type: object`; top-level `anyOf` запрещён.
  - Подмножество JSON Schema ограничено; условные композиции вида `allOf/if/then` нельзя использовать как runtime assumption для provider schema.
- Decision (`reuse/integrate/build`): `reuse + integrate`
  - Reuse уже существующий post-LLM validator `validate_llm_policy_core_output(...)` для `master_query` contract enforcement.
  - Integrate provider-compatible flat response schema вместо inline conditional schema.
- Rejected options:
  - Оставить текущий inline `allOf/if/then` и жить на fallback.
  - Отключить structured outputs глобально как permanent path.

## Root cause (mandatory)

- Symptom:
  - На local realism run `booking-dev-p1.6-20260306-a1-r6` policy-core регулярно получает OpenAI `400 invalid_request_error` на `response_format 'llm_policy_core_output'`.
  - Runtime после этого системно уходит в fallback без `response_format`, то есть degrade-path становится обычным маршрутом.

- Minimal reproduction:
  1. `nl -ba truffles-api/app/services/intent_service.py | sed -n '366,430p'`
  2. `nl -ba truffles-api/app/schemas/intent.py | sed -n '492,517p'`
  3. `python3 - <<'PY'\nimport subprocess\nsince='2026-03-06T03:26:20Z'\ntext=subprocess.check_output(['docker','logs','--since',since,'truffles-api-p1.6-cdc8c2a'], stderr=subprocess.STDOUT, text=True, errors='replace')\nprint(text.count(\"Invalid schema for response_format 'llm_policy_core_output'\"))\nPY`

- Evidence:
  - `truffles-api/app/services/intent_service.py:366`
    - `_build_policy_core_response_format(...)` строит root schema с top-level `allOf`.
  - `truffles-api/app/services/intent_service.py:2233`
    - этот schema передаётся в `llm.generate(... response_format=policy_response_format)`.
  - `truffles-api/app/schemas/intent.py:493`
    - `master_query` contract уже валидируется после LLM и не требует provider-level `allOf/if/then`.
  - `/tmp/booking_quality/booking-dev-p1.6-20260306-a1-r6/manual_audit.json`
    - run остановлен как non-canonical после повторяющихся runtime architecture blocker-ов.
  - Branch runtime logs on `truffles-api-p1.6-cdc8c2a`
    - repeated `Invalid schema for response_format 'llm_policy_core_output'`.

- Five Whys:
  1. Почему provider отвергает `response_format`: root schema построен с top-level `allOf`.
  2. Почему у нас вообще есть top-level `allOf`: builder закодировал `master_query` conditional rules прямо в provider schema.
  3. Почему это ошибка архитектурно: provider schema должен быть transport-compatible, а semantic contract enforcing уже живёт в validator layer.
  4. Почему runtime остаётся опасным: при каждом reject structured-output path silently деградирует в plain JSON parsing.
  5. Почему это блокирует P1.6: realism/lock измеряют уже degraded runtime, а не intended single-owner contract path.

- Root cause statement:
  - Policy-core response-format schema смешал provider transport contract и semantic validation contract: inline top-level `allOf/if/then` сделал OpenAI Structured Outputs несовместимыми, из-за чего runtime системно падает в fallback.

- Fix mechanism:
  - Упростить provider schema до OpenAI-compatible flat object contract.
  - Перенести `master_query` conditional enforcement целиком в `validate_llm_policy_core_output(...)`, где он уже частично реализован.
  - Явно сохранять `structured_output_fallback_used` в decision metadata/quality evidence, чтобы degrade-path был наблюдаемым, а не тихим.

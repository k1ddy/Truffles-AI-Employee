## Architecture verdict (binding)
- The remaining closure problem is no longer a single bad phrase.
- The remaining closure problem is also not only a downstream runtime loss.
- The binding architectural reading of `r73` is:
  - policy-core missed the row;
  - runtime arbitration compressed the missed row into generic info;
  - the current contract still lacks a complete owner matrix over active pending-question operations.
- `pending_question_target` is currently used inconsistently in code. The target architecture for the remaining closure phase is:
  - `expected_reply_type` and active pending-question contract remain the resume axis;
  - `pending_question_target` is reserved for the interaction target of the current side-question/follow-up;
  - `active_question_relation` becomes mandatory for any turn that operates over an active pending question.
- Therefore the open family must not be implemented as another `master info` variant. It must be modeled as its own active-question relation.

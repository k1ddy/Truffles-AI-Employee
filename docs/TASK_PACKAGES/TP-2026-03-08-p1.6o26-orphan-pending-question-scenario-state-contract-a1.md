  - Turn `7` is tagged as `ask_about_requested_slot` and requires `pending_question_act=ask_about_requested_slot`, `pending_question_target=time`, `question_contract expected_reply_type=time`.
  - The same dialog already passed through `handoff` and `check_booking`, and the previous valid runtime turn (`6`) no longer had active `expected_reply_type=time`.
  - Runtime coherently treats turn `7` as a generic booking clarify (`service_choice`) rather than an active pending-slot follow-up, so the failure is `expected_meta_mismatch` / `expected_trace_miss`, not a runtime owner miss.
  - Current generator/governance tracks tags per turn, but does not track whether pending-slot interaction is still semantically active at that point in the dialog.

- Five Whys:
  1. Why did `r25` fail: scenario expected pending-question interaction evidence on a turn where runtime no longer had active slot-question context.
  2. Why did scenario expect that: tag-based expectation helpers inject pending-question meta/trace for `ask_about_requested_slot` without checking preceding dialog state.
  3. Why was preceding state wrong for that family: earlier turns (`handoff`, `check_booking`, completed slot fill) had already cleared the active `time` reply contract.
  4. Why did process not catch this before the expensive run: scenario-contract preflight validates coverage shape, but not stateful validity of pending-question families.
  5. Why did this surface now: `P1.6o25` removed the previous `check_booking -> confirm` governance bug, so the next missing scenario-state contract became the first blocker.

- Root cause statement:
  - scenario generation/governance models pending-question families statically by tag, but not statefully by active reply contract; orphan slot-question turns are therefore emitted and accepted even after the dialog has already left the pending-slot state.

- Fix mechanism:
  - add deterministic stateful sanitization so pending-question tags only survive when the preceding dialog context still carries active `reply_type=time`;
  - downgrade orphan pending-question turns to generic booking clarify expectations (`service_choice`) instead of pending-slot interaction;
  - extend scenario-contract preflight to reject orphan pending-question turns before expensive runs.

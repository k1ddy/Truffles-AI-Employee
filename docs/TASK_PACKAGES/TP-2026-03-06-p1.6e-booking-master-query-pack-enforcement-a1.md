  4. Why is that a contract violation: once the system detects the `master` conflict, it must enforce a safe path, not log and continue the conflicting output.
  5. Why does this persist in code: stale tests still ratify the old behavior, so the bad path remained accepted.

- Root cause statement:
  - in booking-active turns, the centralized semantic guard detects `master_query` vs `catalog.service_query` conflict but does not enforce a safe outcome; combined with booking-memory service carryover and stale tests, this leaves `pricing` as the user-visible answer.

- Fix mechanism:
  - turn `master_signal_override_blocked` from observability-only into centralized enforcement for booking-active `master_query`
  - reuse `build_master_reply_from_pack(...)` to answer from pack data when service context is available; otherwise fail-closed to clarify
  - replace stale tests that currently encode `pricing` as the expected behavior

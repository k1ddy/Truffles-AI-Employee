- Five Whys:

  5. Why did it surface now: `P1.6o34` removed the earlier explicit-time overclaim, so the broader mixed target-axis leak became the next first blocker.

- Root cause statement:
  - scenario taxonomy conflates targeted pending-question families (`ask_about_requested_slot`, `slot_constraint`, `slot_compare`) with the resume-only mixed family, so `mixed_fill_plus_question` inherits `pending_question_target` evidence that runtime does not and should not emit by default.

- Fix mechanism:
  - split targeted pending-question tags from mixed resume-only tag in scenario target-axis injection;
  - update deterministic regressions so mixed family keeps only resume contract (`expected_reply_type`) while targeted families keep target-axis evidence;
  - then run one fresh guarded rerun `r37`.

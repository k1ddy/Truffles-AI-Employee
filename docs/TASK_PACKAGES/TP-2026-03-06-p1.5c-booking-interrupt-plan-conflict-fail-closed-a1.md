## Root cause (mandatory)

- Symptom:
  - `pytest -q truffles-api/tests/test_message_endpoint.py` still has one red runtime contract: booking-interrupt on an explicit hours question can end in unrelated `price_query`.

- Minimal reproduction:
  1. `pytest -q truffles-api/tests/test_message_endpoint.py -k booking_interrupt_hours_contract_blocks_price_takeover -vv`
  2. Reproduce the same path with a policy plan:
     - `action=fact`
     - `tool_action=info`
     - `pack_refs=["master"]`
     - booking context active
     - user text: `Когда у вас работают?`

- Evidence:
  - `truffles-api/app/routers/webhook/decision.py`
    - policy-owned `info` refs are passed into booking-interrupt as `policy_info_set`.
  - `truffles-api/app/routers/webhook/booking.py`
    - booking-interrupt re-evaluates `master` against turn text via `resolve_master_intent(...)`.
    - when `master_resolution.explicit` is false, `master` is removed.
    - after that, the path can fall through to `service_matcher` / `truth_gate`.
  - Reproduction output:
    - `decision_meta.intent=price_query`
    - `decision_meta.source=service_matcher`
    - `decision_meta.booking_info_intents=["price_query"]`
    - `truth_gate_mock.assert_not_called()` passes, but `service_matcher_mock` is called.

- Five Whys:
  1. Why does an hours question end as `price_query`: booking-interrupt strips the plan-owned `master` ref and then falls back to generic semantic matchers.
  2. Why is that wrong: deterministic boundary logic is changing the runtime semantic outcome after the LLM plan.
  3. Why is it dangerous: the user gets a plausible but irrelevant FACT instead of a safe contract outcome.
  4. Why didn’t earlier blocks remove it: the leak only appears after stale tests and wrong patch-target noise were removed.
  5. Why must this block be fail-closed: single-owner architecture allows boundary validation/blocking, but not semantic re-routing on conflict.

- Root cause statement:
  - Booking-interrupt does not distinguish plan-owned `info` refs from heuristic refs; when a plan-owned ref conflicts with explicit interrupt evidence, runtime strips the ref and falls through to secondary semantic matchers instead of blocking.

- Fix mechanism:
  - Add a policy validation guard in the LLM policy `info` booking-interrupt path.
  - If explicit user interrupt info signals and plan-owned `info` refs conflict, emit a traced/meta-observable clarify response and stop before `_handle_booking_interrupt` can fall through to `service_matcher/truth_gate`.

## Invariant

1. Deterministic booking-interrupt logic must not rewrite a plan-owned `info` decision into a different FACT.
2. Conflict between plan-owned refs and explicit user interrupt evidence must fail closed.
3. No new phrase/regex semantic routing may be introduced; only existing resolver outputs may be compared.

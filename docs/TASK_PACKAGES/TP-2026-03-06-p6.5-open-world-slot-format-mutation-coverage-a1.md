## Root cause (mandatory)

- Symptom:
  - the generator now covers language/script/noise/paraphrase surfaces, but it still mostly emits one canonical slot format for dates, times, and phones.

- Minimal reproduction:
  1. inspect `scripts/booking_dialog_scenarios.py` for `slot_format_profile` / format mutation support
  2. `rg -n "slot_format|phone_format|time_format|date_format" scripts/booking_dialog_scenarios.py truffles-api/tests/test_booking_dialog_scenarios_script.py`
  3. observe there is no dedicated slot-format mutation family

- Evidence:
  - `scripts/booking_dialog_scenarios.py`
    - booking/time/phone turns currently reuse one formatting surface from context values
  - `docs/TASK_PACKAGES/TP-2026-02-19-llm-first-firebreak-program.md`
    - open-world battery requires adversarial phrasing and noisy variants, which includes realistic slot formatting drift

- Five Whys:
  1. Why is open-world proof still incomplete: slot values appear in only one dominant format.
  2. Why is that risky: real user turns vary in phone, date, and time formatting even when intent is unchanged.
  3. Why do current tests miss it: they preserve the same slot text layout across most generated cases.
  4. Why should this be fixed in the generator: this is an evidence-coverage problem, not a runtime ownership problem.
  5. Why is this block atomic: slot-format mutation is one orthogonal surface family and can be tested deterministically.

- Root cause statement:
  - scenario generation lacks a reusable, contract-preserving mutation family for time/phone/date formatting drift.

- Fix mechanism:
  - add `slot_format_profile=canonical|variant`
  - rewrite a seed-stable subset of slot-bearing text into alternative date/time/phone formats while preserving `tags` and `expect`
  - add deterministic tests and metadata coverage

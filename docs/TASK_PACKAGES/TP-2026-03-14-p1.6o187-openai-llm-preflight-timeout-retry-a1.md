## Root cause (mandatory)

- Symptom:
  - `p1.6o186-l2-dev-20260314-a1-r1` and `p1.6o186-l2-dev-20260314-a1-r2` both stopped before scenario generation with `stop_reason=invalid_openai_preflight` and `reason=probe_error:TimeoutError` for purpose `llm`.
- Minimal reproduction:
  1. run guarded proof lane `P1.6o186` on parity-verified runtime `http://127.0.0.1:18184`;
  2. let `ops/diagnose.py llm-quality` execute hard OpenAI preflight for `purpose=llm`;
  3. observe a single `TimeoutError` from `urllib.request.urlopen`;
  4. current preflight returns invalid immediately with no retry, so run ends before `scenarios.json` / `responses.jsonl` / `trace_bundle.jsonl` exist.
- Evidence:
  - `/tmp/booking_quality/p1.6o186-l2-dev-20260314-a1-r1/summary.json`

  - `/tmp/booking_quality/p1.6o186-l2-dev-20260314-a1-r2/manual_audit.json`
  - `ops/diagnose.py`
  - `truffles-api/tests/test_booking_quality_openai_preflight.py`
- Five Whys:
  1. Why did both proof attempts stay invalid? Because the `llm` OpenAI preflight failed on `TimeoutError` before scenario execution.
  2. Why does one timeout invalidate the whole run? Because preflight fail-closes immediately on the first transport timeout.
  3. Why is that a blocker instead of product evidence? Because no scenarios or turns ran, so no admissible first-fail family was surfaced.
  4. Why is this specifically a tooling/proof blocker? Because runtime parity, webhook secret, and other preflight checks passed; the failure is isolated to OpenAI transport probing.
  5. Why does a bounded retry fit? Because timeout/url transport faults are transient classes and the official OpenAI client treats them as retryable, while auth/quota/rate-limit remain non-retryable hard failures.
- Root cause statement:
  - `llm` OpenAI preflight is too brittle for proof admission: a single transient timeout/url transport fault invalidates the entire guarded run before any product evidence is collected.
- Fix mechanism:
  - add one bounded retry with short backoff for retryable transport preflight failures (`TimeoutError`, `socket.timeout`, retryable `url_error`, selected transient HTTP statuses), keep hard fail for auth/quota/rate-limit/invalid key, and add targeted unit coverage.

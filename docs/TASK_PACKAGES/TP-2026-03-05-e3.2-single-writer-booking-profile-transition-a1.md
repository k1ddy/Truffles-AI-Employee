## Название/цель
Внедрить единый deterministic transition-owner для цепочки `tool outcome -> booking state/expected_reply -> profile materialization`, чтобы исключить drift между `appointments`, `users`, `decision_meta/trace` и убрать повторяемые semantic/data continuity дефекты при масштабировании.

## Root cause (mandatory)
- Symptom:
  - Семантические блокеры и data continuity drift повторяются на стыке `tool -> expected_reply -> booking/profile`.
- Minimal reproduction:
  1. Прогон acceptance lock на firebreak runtime.
  2. Проверка top-failures (`mix_info_booking`, `booking_prompt_leak`, `stale_booking_carryover`).
  3. Сверка `appointments` и `users` по bot-path.
- Evidence:
  - `/tmp/booking_quality/booking-lock-20260305-firebreak-e2-a1-r22/summary.json`
  - `/tmp/booking_quality/booking-lock-20260305-firebreak-e2-a1-r23/summary.json`
  - `truffles-api/app/routers/webhook/decision.py` (разрозненные update-ветки вокруг tool handling)
  - `truffles-api/app/services/tool_registry_service.py` (частичная contact continuity логика)
- Five Whys:
  1. Почему дефект повторяется? — Переходы состояния после tool-outcome применяются в нескольких местах.
  2. Почему это критично? — `expected_reply`, `booking_state` и `profile sync` могут расходиться между собой.
  3. Почему drift попадает в acceptance? — Контракт не имеет одного owner-а для mutation order.
  4. Почему локальные фиксы не закрывают класс целиком? — Они лечат симптомы конкретной ветки, но не нормализуют цепочку перехода.
  5. Почему риск растет при масштабировании? — Больше доменов и сценариев увеличивают число edge-path, где multi-writer расходится.
- Root cause statement:
  - В runtime-core нет single-writer контракта для booking/profile transition после tool execution, из-за чего semantic/data continuity восстанавливается частично и неустойчиво.
- Fix mechanism:
  1. Вынести единый transition-owner helper (pure contract decisions + deterministic mutations).
  2. Подключить его в `decision.py` как единственную точку применения booking/profile transition в tool-handled path.
  3. Убрать дублирование phone/profile resolution между `decision.py` и `tool_registry_service.py` через shared helper.
  4. Добавить fail-closed quality signal для отсутствия transition evidence в `calendar.book_slot:ok`.

## Canon sync delta (binding)
- `STRATEGY/REQUIREMENTS.md` must define:
  - `expected_reply_type` as the resume axis;
  - `pending_question_target` as the interaction target;
  - `active_question_relation` as mandatory for active pending-question turns;
  - exactly one `interaction_owner` per inbound turn;
  - allowed degrade only when relation/resume are preserved with explicit `reason_code`, `decision_meta`, and `decision_trace`;
  - forbidden compression examples that remain contract-invalid even when surface text looks acceptable.
- Base canon must also define active pending-question families as owner-matrix rows with one semantic contract, one owner, allowed degrade, and forbidden compression per row.
- `SPECS/CONSULTANT.md` must define booking interrupts as side-questions over an active interaction row, not just “answer fact then return to booking prompt”.
- `SPECS/CONSULTANT.md` and `SPECS/ARCHITECTURE.md` must define a first-class persisted `InteractionState` with minimum fields:
  - `resume_slot`
  - `interaction_target`
  - `interaction_relation`
  - `interaction_owner`
  - `grounded_referents`
  - `confirmation_state`
  - `degrade_reason`
- `SPECS/ARCHITECTURE.md` must define that deterministic boundaries may validate / block / degrade but may not invent a new interaction owner row after policy-core without an explicit contract reason-code.
- `docs/runbooks/BOOKING_CONFIRM_VERIFY.md` must require structured oracle assertions for `pending_question_target` / `active_question_relation` / `interaction_owner` whenever active pending-question continuity is under test.

## Root cause (mandatory)

- Symptom:
  - after the evaluator false-positive fix and runtime launch recovery, fresh canonical rerun `p1.6o134-l2-dev-20260313-a1-r2` is still blocked at preflight with `invalid_run_economy_preflight (lock_fingerprint_unchanged_after_non_canonical)`.
- Minimal reproduction:
  1. Open `/tmp/booking_quality/p1.6o132-l2-dev-20260313-a1-r1/summary.json`.
  2. Confirm `infra_valid=false`, `run_integrity_valid=false`, `artifact_integrity.valid=true`, `manual_audit.status=done`, and root causes include `runtime_pipeline_latency_budget_exceeded` plus `non_canonical_partial_dialog_execution`.
  3. Confirm `/tmp/booking_quality/.run_economy_lock_state.json` now points to that same non-canonical lock fingerprint.
  4. Start a recovered runtime on `127.0.0.1:18184` with the same repo/runtime contour and rerun canonical lock without code delta.
  5. Observe `p1.6o134-l2-dev-20260313-a1-r2` stop at `invalid_run_economy_preflight` because current admission logic only treats previous process/preflight stop reasons as eligible unchanged-fingerprint retries.

  - `/tmp/booking_quality/p1.6o134-l2-dev-20260313-a1-r2/manual_audit.json`
  - `ops/diagnose.py`
- Five Whys:
  1. Why is fresh rerun blocked after runtime recovery? Because `run_economy` sees the same lock fingerprint and the previous lock was non-canonical.
  2. Why does it still block despite real recovery? Because eligibility is currently derived only from previous lock `stop_reason`.
  3. Why is that insufficient here? Because `P1.6o132` stopped with `max_failures_reached:1`, but its non-canonicality was driven by audited infra/runtime contamination and partial execution, not by a completed semantic lock contour.
  4. Why does that matter architecturally? Because proof-lane admission becomes stricter than the class-routing process itself and prevents truthful post-recovery evidence from ever being collected.
  5. Why not just bypass the gate manually? Because that would hide the process defect and weaken the anti-loop contract instead of making retry eligibility explicit and machine-checkable.
- Root cause statement:
  - `run_economy` lock retry admission currently models previous non-canonical locks too coarsely: it only recognizes preflight/process stop reasons, so an audited `infra_valid=false + run_integrity_valid=false` lock remains permanently non-rerunnable even after a real runtime recovery outside repo code.
- Fix mechanism:
  - preserve the default lock anti-loop block;
  - extend explicit `--allow-non-canonical-lock-retry` eligibility to audited non-canonical locks that prove `infra_valid=false`, `run_integrity_valid=false`, `artifact_integrity.valid=true`, and `manual_audit.status=done`;
  - keep semantic-red locks with valid infra or unaudited/incomplete infra locks blocked;
  - add positive/negative regression tests around this boundary.

- Symptom:
  - quality chain already blocks on `semantic_valid`, threshold breaches, and manual audit/process gates, but the core open-world invariants from the remediation program are still absent from runtime metrics and thresholds.

  4. `rg -n "fact_without_evidence_rate|irrelevant_fact_rate|booking_commit_without_required_contact|semantic_override_rate|stale_state_leak_rate" ops/diagnose.py scripts/llm_quality_guarded.sh scripts/quality_chain_controller.sh` -> no hits

- Evidence:
  - `ops/diagnose.py`
    - coarse thresholds exist for `strict_pass_rate`, `hard_fail_rate`, `degraded_fallback_rate`, etc.
    - `semantic_valid` already becomes false on threshold breaches
  - `scripts/quality_chain_controller.sh`
    - chain progression depends on summary validity and checklist state, so new invariant thresholds can block without inventing a new control plane
  - inventory command above confirms the five required remediation invariants are not yet wired into the gate

- Five Whys:
  1. Why can known bad behaviors still pass the gate: the gate measures generic rates, not the critical remediation invariants.
  2. Why is that unsafe: a run can stay green on coarse metrics while violating the contract we just fixed in code.
  3. Why is this happening: invariant data is not normalized into summary metrics and therefore never reaches threshold logic.
  4. Why is that a root cause: acceptance still depends on case outcomes instead of open-world contract signals.
  5. Why must this block happen now: after `P3` and `P4.1`, these invariants define whether the branch is actually safe to promote.

- Root cause statement:
  - the quality pipeline already has a blocking threshold mechanism, but it does not ingest or enforce the remediation invariants that matter for LLM-first contract safety.

- Fix mechanism:
  - compute/normalize the five invariants into `summary.metrics`
  - add thresholds/directions for them
  - make threshold breaches block `semantic_valid`, guarded admission, and chain progression
  - cover the new gates with deterministic tests in status/chain-controller suites

## Invariant

1. Invariants are measured as machine-readable metrics, not manual notes.
2. Promotion gating stays single-path: `summary -> threshold breach -> semantic_valid false -> chain blocked`.
3. No threshold downgrade and no advisory-only shadow gate.

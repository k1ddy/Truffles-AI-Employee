- Five Whys:

- Root cause statement:
  - the system can semantically detect specialist referents during active booking, but booking runtime still has no explicit specialist owner contract, so specialist follow-up turns are compressed either into generic `master` info expectations on the taxonomy side or into generic booking progression on the runtime side.

- Fix mechanism:

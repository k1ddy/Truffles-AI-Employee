- Five Whys:
  1. Why did turn 9 fail: scenario expected a fresh `service_choice` contract while runtime advanced to `name`.
  2. Why did scenario expect `service_choice`: active `time` pending-question context was lost before the explicit time answer.
  3. Why was context lost: turn 4 had generic `info` tags and generic `info` is not in `PENDING_QUESTION_CONTEXT_PRESERVE_TAGS`.
  4. Why did later interrupts not restore the correct context: they preserve only the already-lost `None` state.
  5. Why did the failing turn still need one more fix after preserving context: booking-tag explicit time fill under active `time` collect was not normalized, so stale `service_choice` override could survive on the final turn.
  6. Why is this a model gap instead of phrase noise: the failure is caused by state-machine coverage of interruption classes plus canonical slot-fill normalization, not by one wording variant.

- Root cause statement:
  - scenario state tracking omits generic `info` from pending-question context preservation, and the same state machine also lacks canonical normalization for booking-tag explicit time fills under active `time` collect, so a normal info interruption clears `active_reply_type` and the next grounded time answer can keep stale `service_choice` override instead of re-entering the canonical `time -> name` resume path.

- Fix mechanism:
  - extend the scenario pending-question preservation contract to include generic `info` turns;
  - normalize booking-tag explicit time fills under active `time` collect into canonical `time` tags and scrub stale `service_choice` expectation overrides;
  - add deterministic regressions for both the direct normalization and the full `booking -> slot question -> info -> grounded time answer` chain;
  - rerun guarded `dev L2` only after deterministic scenario checks are green.

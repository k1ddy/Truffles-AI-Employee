- Five Whys:
  1. Why does runtime keep reconstructing semantics: the payload does not carry enough structured meaning.
  2. Why does the payload not carry enough meaning: prompt/schema/runtime contract stopped at `service/datetime/name` slots.
  3. Why is that insufficient: follow-up and capability questions are about objects and abilities, not only booking slots.
  4. Why does this create downstream drift: later layers infer missing meaning from stale state, phrase hints, or fallback logic.
  5. Why is this a root mechanism: `P1.6o2/P1.6o3` cannot be reliable if the semantic envelope remains underspecified.
- Root cause statement:
  - semantic meaning needed for runtime arbitration is under-specified in the current policy-core payload, so downstream layers reconstruct business meaning from fragmented slots and carryover instead of consuming an explicit contract.
- Fix mechanism:
  - extend the semantic envelope with backward-compatible explicit fields for object/capability/time-scope/resolution intent;
  - teach prompt and schema to emit them;
  - plumb them into `decision_meta/trace` without yet changing final routing behavior beyond contract exposure.

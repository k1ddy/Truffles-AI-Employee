## Root cause (mandatory)

- Symptom:
  - `P1.6o172` strict-audited rerun surfaced `dialog 1 / turn 6 / "Можно к мастеру Мадина?"`, where runtime emitted `action=reply`, `intent=master`, `source=truth_gate`, `booking_interrupt_info=true`, while scenario correctly required `pending_question_target=specialist`, `active_question_relation=referent_followup`, and `expected_reply_type=time`.
- Minimal reproduction:
  1. keep booking active with `expected_reply_type=time`;
  2. drive several info interrupts so the turn reaches the late degraded invalid-schema rescue path;
  3. send an explicit named-specialist booking request like `"Можно к мастеру Мадина?"`;
  4. observe that branch-catalog hint is unavailable, late secondary specialist hint is budget-skipped, and the turn falls through to generic `truth_gate/master` info reply.

- Five Whys:
  1. Why did runtime answer generic master info? Because the invalid-schema specialist-followup rescue returned `None` and execution fell through to later master-info/truth-gate handling.
  2. Why did the rescue return `None`? Because it only preserves specialist followup when it has a resolved specialist hint.
  3. Why was no specialist hint resolved? Because the branch catalog had no single match and the secondary specialist-hint stage was skipped on the webhook budget boundary.
  4. Why did budget skip matter this late? Because the rescue depends on a late hint call instead of a bounded deterministic surface fallback for explicit named-specialist wording.
  5. Why is that a contract bug? Because the runtime already knows this is an active booking `time` followup, so falling through to generic master info changes interaction owner instead of merely losing personalization.
- Root cause statement:
  - invalid-schema specialist-followup recovery depends on a resolved specialist hint; when branch catalog does not resolve and the late secondary hint is budget-skipped, explicit named-specialist booking requests are misrouted into generic master info fallback instead of staying on the existing specialist-followup collect owner.
- Fix mechanism:

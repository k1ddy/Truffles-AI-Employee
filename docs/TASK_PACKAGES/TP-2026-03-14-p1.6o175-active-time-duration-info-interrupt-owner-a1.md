## Root cause (mandatory)

- Symptom:
  - `P1.6o174` strict-audited rerun surfaced `dialog 1 / turn 3 / "Что насчет времени выполнения?"`, where scenario expected duration info (`info_sections=[duration,service_duration]`) with `expected_reply_type=time`, but runtime emitted `action=reply`, `intent=booking`, `source=booking_slot_guidance`, and no duration info evidence.
- Minimal reproduction:
  1. keep booking active with `expected_reply_type=time` and a named specialist already selected;
  2. let a prior factual info interrupt preserve `time` resume;
  3. send an explicit duration question like `"Что насчет времени выполнения?"`;
  4. observe that runtime keeps `booking_slot_guidance` instead of entering `booking_info_interrupt(duration)`.

- Five Whys:
  1. Why did runtime answer slot guidance instead of duration info? Because the turn stayed on `booking_slot_guidance` and never entered info-interrupt handling.
  2. Why did it stay on slot guidance? Because `_resolve_policy_collect_interrupt_arbitration(...)` returned early on the broad active-time slot-question preserve guard.
  3. Why did that early return fire? Because `llm_policy_core` emitted `collect + capability=duration + pending_question_act=ask_about_requested_slot + pending_question_target=time` on the surfaced turn.
  4. Why is that a contract bug? Because explicit duration info interrupts under active booking should preserve the `time` resume contract via `booking_info_interrupt`, not suppress duration info completely.
  5. Why is this bounded to runtime ownership? Because scenario and audit already agree on the missing duration info; the drift happens before info-interrupt routing is admitted.
- Root cause statement:
  - the broad active-time slot-question preserve guard in `_resolve_policy_collect_interrupt_arbitration(...)` swallows explicit duration info turns before `duration` info refs can be admitted, so runtime falls through to `booking_slot_guidance` instead of `booking_info_interrupt(duration)`.
- Fix mechanism:
  - add one bounded explicit-duration exception ahead of the broad active-time slot-question preserve guard, so surfaced duration info turns can rewrite `collect -> info` while genuine time-guidance/hours slot-question turns still preserve `booking_slot_guidance`.

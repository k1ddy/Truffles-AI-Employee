## Root cause (mandatory)

- Symptom:
  - `decision.py` still derives semantic info refs from hardcoded token maps and explicit phrase markers inside arbitration path.
- Minimal reproduction:
  - `rg -n "INFO_INTENT_HINTS|_has_explicit_location_or_hours_request|master|specialist" truffles-api/app/routers/webhook/decision.py`
- Evidence:
  - `INFO_INTENT_HINTS` local token map used to derive refs.
  - `_has_explicit_location_or_hours_request` uses built-in explicit markers tuple (address/hours phrases).
  - `_resolve_policy_collect_interrupt_arbitration` uses policy_intent substring checks (`master`/`specialist`) to force info refs.
- Five Whys:
  1. Why core routes by phrase? Historical guard rails for missed refs.
  2. Why needed? Policy payload often lacked structured refs.
  3. Why still in core? Incremental patches accumulated in `decision.py` monolith.
  4. Why harmful now? Creates language/business coupling and latent second semantic owner.
  5. Why not acceptable? Violates Semantic-First Charter (`LLM-first semantic ownership`).
- Root cause statement:
  - Semantic arbitration accumulated inline lexical fallbacks in core instead of relying on owner output + resolver/config layer.
- Fix mechanism:
  - Remove local token/phrase inference from arbitration helpers and derive refs only from structured/ resolver outputs.

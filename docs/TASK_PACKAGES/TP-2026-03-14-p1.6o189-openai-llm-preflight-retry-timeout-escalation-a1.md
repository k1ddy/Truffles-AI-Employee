## Root cause (mandatory)

- Symptom:
  - `p1.6o188-l2-dev-20260314-a1-r1` still stops before scenario generation with `stop_reason=invalid_openai_preflight`, even after `P1.6o187` added retry, because the final `llm` preflight result is `attempts=2`, `retried=true`, `reason=probe_error:TimeoutError`, `elapsed_ms=61927.98`.
- Minimal reproduction:
  1. run guarded proof lane `P1.6o188` on parity-verified runtime `http://127.0.0.1:18184`;
  2. let `ops/diagnose.py llm-quality` execute hard OpenAI preflight for `purpose=llm`;
  3. observe first retryable timeout fail and second retry attempt;
  4. both attempts inherit the same `30s` per-attempt timeout envelope, so both expire before response and run ends before `scenarios.json` / `responses.jsonl` / `trace_bundle.jsonl` exist.
- Evidence:
  - `/tmp/booking_quality/p1.6o188-l2-dev-20260314-a1-r1/summary.json`
  - `/tmp/booking_quality/p1.6o188-l2-dev-20260314-a1-r1/manual_audit.json`
  - `ops/diagnose.py`
  - `truffles-api/tests/test_booking_quality_openai_preflight.py`
- Five Whys:
  1. Why is the rerun still invalid after `P1.6o187`? Because both `llm` preflight attempts timed out.
  2. Why did both attempts time out? Because retry reused the same capped per-attempt timeout budget.
  3. Why is that a blocker instead of product evidence? Because no scenarios or turns ran, so no admissible semantic first-fail family surfaced.
  4. Why is retry alone insufficient? Because retry without timeout escalation only repeats the same failing transport envelope.
  5. Why is bounded timeout escalation the right next slice? Because it preserves the hard preflight gate while removing the newly surfaced budget-coupling brittleness.
- Root cause statement:
  - `llm` OpenAI preflight remains too brittle because retry does not escalate beyond the original capped per-attempt timeout budget, so persistent-but-recoverable transport latency still invalidates the whole guarded run before any product evidence is collected.
- Fix mechanism:
  - add a bounded larger second-attempt timeout envelope for retryable `llm` preflight failures only, keep retry count fixed at two, keep auth/quota/rate-limit failures fail-closed, and add targeted unit coverage for timeout budget escalation.

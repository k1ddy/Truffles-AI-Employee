## Schema contract (binding)
- `expected_reply_type` is the resume axis for the currently open slot.
- `pending_question_target` is the interaction target of the current side-question/follow-up.
- `active_question_relation` is mandatory when the user operates over an active pending question.
- Child rows may not rely on raw text phrases to infer the relation in runtime core; relation must come from semantic owner or be deterministically validated at boundary.

## Degrade matrix (binding)
- For `M1`, `M2`, `M3`, `M4`, `M7`, `M8`, `M10`, `M11`, `M12`, `M13`, and `M14`, degrade is admissible only if it:
  - preserves the same `active_question_relation`;
  - preserves `expected_reply_type` as the current resume owner after any deterministic grounding boundary;
  - emits explicit `reason_code`, `decision_meta`, and `decision_trace` evidence.
- For `M7` and `M10`, degrade must never end in generic `master` truth reply counted as success.
- For `M11`, degrade must never jump straight to `policy_timeout_degrade` handoff while the requested-slot row is still the active owner and no row-scoped timeout limit was recorded.
- For `M12`, degrade must never fall back to generic `booking_prompt` or stale `service_choice` while an alternate-time availability probe is unresolved under active `name` collect.
- For `M13`, degrade may resume `name` only after deterministic `question_contract` grounding has already consumed `datetime`; scenario/oracle must not keep the pre-grounding `expected_reply_type=time` as the final contract for that turn.

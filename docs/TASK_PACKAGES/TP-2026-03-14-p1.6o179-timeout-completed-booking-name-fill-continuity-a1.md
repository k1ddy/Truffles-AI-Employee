- Five Whys:
  1. Why did the rerun fail? Because timeout degrade returned a FACT-like fallback without evidence.
  2. Why did timeout degrade choose fact fallback? Because no bounded timeout continuity branch claimed the turn before `pack_fact_fallback` eligibility.
  3. Why did no bounded timeout continuity branch claim it? Because the current turn completed booking collection, so `matched_booking_followup_state` is empty and `expected_reply_type` has already been cleared.
  4. Why is that a bug? Because the same turn already has matched slot evidence and complete booking state, which should continue through the existing booking completion/handoff path rather than an unrelated factual fallback.
  5. Why is this not the old `P1.6o105` family? Because `P1.6o105` only covered incomplete booking slot-fill followup; `P1.6o178` surfaces the adjacent contour where the current matched fill completes booking collection.
- Root cause statement:
  - timeout boundary preserves matched followup only while a next missing-slot prompt exists; when the matched turn completes booking collection, `expected_reply_type` is cleared, no completion-boundary branch reuses the now-complete booking state, and runtime falls through to `pack_fact_fallback`.
- Fix mechanism:
  - add one bounded timeout continuity branch that detects `matched_expected_reply` + complete booking state without booking reference, routes the turn into existing `_handle_booking_flow(...)` completion/handoff logic, and preserves explicit timeout provenance in `decision_meta/decision_trace`.

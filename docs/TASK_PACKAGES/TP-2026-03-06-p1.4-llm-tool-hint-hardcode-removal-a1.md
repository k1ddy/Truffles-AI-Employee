## Root cause (mandatory)

- Symptom:
  - LLM policy core tool-execution path строит `info_sections_hint` из `message_text` и детерминированных info классификаторов.
  - Это приводит к lexicon-dependent поведению и второму semantic owner в core.

- Minimal reproduction:
  1. `rg -n "info_sections_hint" truffles-api/app/routers/webhook/decision.py`
  2. `sed -n '12680,12770p' truffles-api/app/routers/webhook/decision.py`
  3. `rg -n "catalog_location_passes_parking_info_hint" truffles-api/tests/test_message_endpoint.py`

- Evidence:
  - `truffles-api/app/routers/webhook/decision.py`:
    - `info_sections_hint` заполняется через `_detect_info_class_intents(message_text, ...)`.
    - `explicit_location_or_hours` проверяется через `_has_explicit_location_or_hours_request(message_text, ...)`.
  - `truffles-api/tests/test_message_endpoint.py`:
    - тесты ожидают `info_sections_hint` из message-text сигналов.

- Five Whys:
  1. Почему hints берутся из текста: исторический rescue path до LLM.
  2. Почему остались в core: LLM policy core интегрирован поверх legacy эвристик.
  3. Почему это проблема: детерминизм влияет на semantic hints, нарушая single-owner контракт.
  4. Почему не заметили: тесты закрепили message-text поведение как норму.
  5. Почему фикс сейчас: P1 требует LLM-owned семантику и business-agnostic core.

- Root cause statement:
  - LLM tool path использует legacy message-text heuristics для semantic hints, что нарушает single semantic owner и вводит lexicon hardcode в core.

- Fix mechanism:
  - Убрать message-text fallback в LLM tool path, полагаться только на LLM `pack_refs` (и tool defaults).
  - Обновить contract tests, чтобы hints шли из LLM plan, а не из message_text.

## Invariant

1. В LLM policy core `info_sections_hint` определяется только из LLM plan (`pack_refs`) и tool defaults.
2. Message-text/lexicon heuristics не используются в LLM tool path.
3. Тесты фиксируют отсутствие message-text влияния на hints.

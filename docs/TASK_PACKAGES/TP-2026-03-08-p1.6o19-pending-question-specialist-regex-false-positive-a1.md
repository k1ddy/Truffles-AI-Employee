## One web search (mandatory before implementation)

- Query: `site:docs.python.org re IGNORECASE character class regex`
- Time (UTC): `2026-03-08T07:50:00Z`
- Sources:
  - `https://docs.python.org/3/library/re.html`
- Ready solutions found:
  - `re.IGNORECASE` also affects character-class matching, so a pattern intended for title-case names can accidentally match lowercase words when the class starts with `[A-Z...]`.
  - case-sensitive name patterns are safer when the contract relies on real proper-name cues rather than generic words.
- Decision (`reuse/integrate/build`): `reuse + integrate`
  - reuse the current target-axis taxonomy and bounded named-specialist family from `P1.6o17`;
  - integrate a stricter proper-name regex instead of broadening runtime or oracle rules;
  - build only the missing false-positive regression around `у вас`.
- Rejected options:
  - weakening `expected_meta_mismatch` / `expected_trace_miss` oracle for this family;
  - adding phrase-specific exclusions like `у вас` in runtime core;
  - removing specialist-target support from taxonomy altogether.

  - The runtime handled the turn as time-target slot question: `pending_question_act=ask_about_requested_slot`, `pending_question_target=time`, `tool_action=calendar.list_slots`, `expected_reply_type=time`.
  - The generated scenario expected `pending_question_target=specialist`, `intent=master`, and `booking_interrupt info_reply` trace.
  - `SPECIALIST_REFERENCE_PATTERNS` currently use `re.IGNORECASE` with `[A-Z...]`, so the pattern `\bу\s+[A-Z...]` matches the lowercase phrase `у вас` and falsely infers a specialist reference.

- Five Whys:
  1. Why did `r14` fail: scenario meta/trace expected a specialist-target interrupt while runtime emitted a time-target slot-question collect path.
  2. Why did scenario expect specialist: `_infer_pending_question_target()` returned `specialist`.
  3. Why did `_infer_pending_question_target()` return `specialist`: `_looks_like_specialist_reference()` matched `у вас`.
  4. Why did it match `у вас`: `SPECIALIST_REFERENCE_PATTERNS` used `re.IGNORECASE` on a title-case name class, so lowercase tokens like `вас` satisfy the class.
  5. Why is that wrong: `у вас` is a generic pronoun phrase, not a named specialist cue, so taxonomy misclassifies a plain time question as specialist-target.

- Root cause statement:
  - specialist-reference regex in scenario taxonomy is too broad because `re.IGNORECASE` turns a title-case proper-name pattern into a generic lowercase word matcher, creating false specialist-target expectations on phrases like `у вас`.

- Fix mechanism:
  - tighten specialist-reference regex to require actual proper-name cues without `re.IGNORECASE` broadening;
  - add deterministic regressions that keep `Могу ли я записаться к Айгерим?` as `specialist` while forcing `Какой у вас есть слоты на эту неделю?` back to `time`.

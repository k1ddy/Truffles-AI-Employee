## Root cause (mandatory)

- Symptom:
  - `calendar.reschedule` and `calendar.cancel` still perform mutation writes plus follow-up sync/reminder writes with independent commits.

- Minimal reproduction:
  1. inspect `_reschedule_booking(...)` and `_cancel_booking(...)` in `truffles-api/app/services/tool_registry_service.py`
  2. inspect subsequent `enqueue_appointment_sync(...)`, `mark_pending_reminders_failed(...)`, `schedule_default_reminders(...)`
  3. verify remaining `commit=True` hits in mutation path

- Evidence:
  - `truffles-api/app/services/tool_registry_service.py`
    - mutation paths still call internal commits after the appointment mutation
  - `truffles-api/app/services/calendar_sync_service.py`
    - enqueue helpers support `commit=False`, so parity can reuse the same mechanism as `P3.2`
  - `truffles-api/app/services/appointment_reminder_service.py`
    - reminder helpers support `commit=False`

- Five Whys:
  1. Why can mutation side effects split: reschedule/cancel still use commit-as-you-go.
  2. Why was create fixed first: create-path was the highest-risk persistence defect.
  3. Why is mutation parity next: remaining independent commits can still leak partial state on change/cancel flows.
  4. Why is this architectural debt: booking protocol is not fully atomic while mutation paths diverge from create-path.
  5. Why is it a separate TP: it changes different flows and needs its own regressions.

- Root cause statement:
  - booking mutation flows still use independent commits instead of the transaction boundary now used for create-path.

- Fix mechanism:
  - inventory remaining mutation commit points
  - reuse `P3.2` boundary pattern for reschedule/cancel
  - add rollback regressions for mutation side effects

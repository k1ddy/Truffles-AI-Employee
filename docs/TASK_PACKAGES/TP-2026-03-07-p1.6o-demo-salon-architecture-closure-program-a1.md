## Target architecture (binding)

- `Semantic envelope`:
  - policy-core contract must explicitly carry the business object and question intent needed for runtime arbitration:
    - `entity_refs`
    - `subject_kind`
    - `capability`
    - `temporal_scope`
    - `resolution_mode`
    - `resolver_id/resolver_version`
  - runtime must stop reconstructing these semantics from scattered post-hoc hints.
- `Canonical dialog state`:
  - one state owner must hold current referents and pending turn contract:
    - `current_referents.service`
    - `current_referents.master`
    - `current_referents.branch`
    - `booking_state`
    - `pending_question_contract`
    - `consult_state`
  - legacy islands such as `service_carryover`, `consult_context`, `class_carryover`, and ad-hoc session fragments may survive only as backward-compatible views during migration, not as independent semantic owners.
- `Referent resolver`:
  - deictic turns (`эта услуга`, `к нему`, `там`, `на выходные`, `в это время`) must resolve from canonical state before retrieval/tool routing;
  - missing referent must produce explicit clarify, not silent fallback to a generic flow.
- `Capability arbitration`:
  - runtime must answer capability questions by contract, not by phrase heuristics:
    - pack/static fact when the question is about business policy or generic schedule;
    - tool/calendar when the question asks for concrete live availability;
    - clarify when the object or capability is unresolved;
    - handoff only when policy/law/service boundary requires it.
- `Boundary determinism`:
  - deterministic code may validate, block, normalize protocol/state, and attach `reason_code`, but it may not invent semantic meaning that the semantic envelope did not carry.
- `Oracle/evidence contract`:
  - acceptance must validate `action/tool_action/info_sections/tool outcomes/trace/meta/outcome`, not byte-identical phrasing;
  - if runtime contract and oracle disagree, the oracle must be corrected before closure.

  - `SERVICE_CARRYOVER_INTENTS = {"pricing", "duration"}` means current service continuity is only modeled for a narrow subset of info turns;

- Five Whys:
  1. Why do blocker families keep resurfacing: the system still has no single canonical semantic state model.
  2. Why is there no canonical semantic state model: semantic responsibility is split between policy-core, controller, answer-interpreter, booking/info/response fallback logic, and ad-hoc carryover stores.
  3. Why does this create phrase-fix pressure: without a canonical referent/capability model, every deictic or follow-up turn looks like a special case.
  4. Why does retrieval/data get blamed incorrectly: many failures never reach the correct fact/tool path because the runtime loses the referent earlier.
  5. Why does the team drift into expensive reruns and patch-fitting: the process lacked a truthfulness contract that forbids declaring closure before full proof.
- Root cause statement:
  - current `demo_salon` runtime is not failing mainly because the LLM is weak or because pack data is absent; it is failing because semantic ownership, dialog state, referent continuity, capability arbitration, and oracle alignment are not modeled as one coherent contract, so the runtime repeatedly reconstructs meaning from scattered heuristics and partial context.
- Fix mechanism:
  - define and implement one canonical semantic contract;
  - define and implement one canonical dialog-state / referent store;
  - introduce one referent resolver and one capability arbitration layer;
  - remove duplicate semantic derivation paths and `_legacy` back-coupling from the active runtime path;
  - align acceptance oracle with the real business-object contract;
  - close the program only on full proof bundle.

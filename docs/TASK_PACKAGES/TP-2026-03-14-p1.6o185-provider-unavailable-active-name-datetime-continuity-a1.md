## Root cause (mandatory)

- Symptom:
  - `p1.6o184-l2-dev-20260314-a1-r1` first-fails at `dialog 1 / turn 8 / "Можно ли забронировать за собой место?"` because runtime ends with `expected_reply_type=time` after `provider_unavailable`, even though active continuity before the turn is `name`.
- Minimal reproduction:
  1. reach active booking state with grounded `service+datetime` and missing `name`;
  2. preserve `expected_reply_type=name` through an info interrupt;
  3. trigger generic booking re-entry that routes to `calendar.book_slot`;
  4. return `tool_decision=provider_unavailable`;
  5. observe `booking_transition_owner.apply_tool_transition_owner(...)` clear `datetime`, after which followup derivation re-computes slot order from service-only state and rewrites followup to `time`.
- Evidence:
  - `/tmp/booking_quality/p1.6o184-l2-dev-20260314-a1-r1/summary.json`
  - `/tmp/booking_quality/p1.6o184-l2-dev-20260314-a1-r1/responses.jsonl`
  - `/tmp/booking_quality/p1.6o184-l2-dev-20260314-a1-r1/trace_bundle.jsonl`
  - `/tmp/booking_quality/p1.6o184-l2-dev-20260314-a1-r1/manual_audit.json`
  - `truffles-api/app/services/booking_transition_owner.py`
- Five Whys:
  1. Why does the turn end on `expected_reply_type=time`? Because followup derivation sees only `service` after the tool path finishes.
  2. Why is only `service` left? Because transition-owner clears `datetime` on negative `calendar.book_slot` outcomes, including `provider_unavailable`.
  3. Why is that wrong here? Because `provider_unavailable` is a transient provider failure, not semantic evidence that the user-provided `datetime` is invalid.
  4. Why does that become first-fail? Because active continuity before the tool call is `name`, so clearing `datetime` forces a deterministic followup rewrite and loses the active child-state contract.
  5. Why did proof surface it as expectation mismatch? Because scenario/trace expectations observe the downstream rewrite, but the executable root cause is the transition-owner state mutation.
- Root cause statement:
  - transient `provider_unavailable` is incorrectly treated like a semantic invalidation inside `apply_tool_transition_owner`, which clears grounded `datetime` and breaks active `name` continuity.
- Fix mechanism:
  - preserve `datetime` for `provider_unavailable` while keeping negative-slot invalidation behavior for true semantic mismatches (`conflict` / `time_mismatch`), then add bounded regressions at transition-owner and endpoint level.

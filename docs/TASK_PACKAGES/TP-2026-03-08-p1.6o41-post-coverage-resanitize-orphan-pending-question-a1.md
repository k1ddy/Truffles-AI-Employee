    - `_sanitize_llm_turns(...)`

- Five Whys:
  1. Why did `r42` abort: scenario contract found a pending-question turn without active `reply_type=time` context.

  4. Why did earlier orphan protections miss it: `P1.6o26` guarded the main sanitize path, not post-coverage mutations.
  5. Why is this process/model gap rather than random noise: generation pipeline order allows invalid final dialog graphs after a later mutation step.

- Root cause statement:
  - scenario generation sanitizes pending-question state before booking-management coverage insertion, but does not resanitize the final dialog batch afterward, so later injected turns can reintroduce orphan pending-question tags and break scenario contract preflight.

- Fix mechanism:

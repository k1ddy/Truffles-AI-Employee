- Five Whys:

  2. Why did runtime go to `hours`: `question_contract` missed and `expected_reply_blocked_by_info=true`, so the collect turn was later eligible for info-interrupt arbitration.
  3. Why did `question_contract` miss: expected-reply datetime validation returned no candidate for `утренние часы`.
  4. Why did datetime validation return no candidate: daypart normalization patterns recognize bare forms like `утро/утром`, but not adjectival variants like `утренние`.
  5. Why is this architectural and not phrase-fitting: the gap is at the normalization boundary for a whole morphological class of daypart constraints, not one isolated sentence.

- Root cause statement:
  - datetime normalization does not recognize adjectival daypart forms, so active time constraints like `утренние часы` fall through the expected-reply boundary and get misrouted into generic `hours` info handling.

- Fix mechanism:
  - extend daypart normalization data to cover adjectival daypart forms;
  - add deterministic boundary tests for datetime validation and info-blocking;
  - add one runtime regression proving the normalized candidate preserves `slot_constraint(time)` instead of `hours` info reply.
